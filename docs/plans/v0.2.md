# Plan: Skillverse 0.2

Status: **built; release pending** (Phase 6 step 3). Supersedes the order in [npm-install.md](npm-install.md): installing the whole plugin from npm moves after 0.2.

## Goal

Two parts, one repo, one npm package (`@jonathanjuliani/skillverse`):

| Part | Installed with | Does |
|---|---|---|
| **Plugin** | Marketplace or a clone | The pane (`/skillverse`, `/sv`), the terminal app (`/skillverse-it`, `/sv-it`), live events to the web app when it runs |
| **Web app** | `npm i -g @jonathanjuliani/skillverse` or a clone | `skillverse run` serves the web view in the background; it scans every agent's skills on its own and shows the plugin's events when a session sends them |

The plugin no longer serves the web view itself. **Open web view** checks for the web app and says what to do when it is missing.

## Decisions

| Question | Decision |
|---|---|
| Web app tech | Plain HTML and JS, no build step; `web/index.html` split into ES modules with clear responsibilities |
| `/sv-it` | In the desktop app: hand Claude a prompt to start the terminal app in the Terminal panel. Elsewhere, or when that fails: print the command |
| Web server owner | The web app only. The plugin finds it, feeds it, and opens it; it does not start one |
| Port | `SKILLVERSE_PORT`, read by the plugin and the CLI (`--port` overrides); default 4317, then the next free one up to 4320 |
| Agents scanned | Claude (`~/.claude/skills`, project `.claude/skills`, enabled plugins), Codex (`~/.codex/skills`), Cursor (`~/.cursor/skills`), Shared (`~/.agents/skills`); more later |
| A skill in two agents | On both globes, linked to each other |
| Claude's list | The scan first; replaced by the session's exact list when the plugin sends it |

## Phases

### Phase 1: plugin commands and port (no web changes) ✔ done

1. `/sv` opens the pane, as `/skillverse` does.
2. `/skillverse-it` and `/sv-it` replace `/skillverse-terminal`:
   - a session on the desktop app (`$.session.surfaces()` has a non-terminal surface): `$.prompt.submit` asks Claude to start `node <plugin>/tui/skillverse.mjs` in the Terminal panel, and to print the command if it cannot;
   - otherwise: print the command (installed plugin path, and `npx @jonathanjuliani/skillverse`).
3. `SKILLVERSE_PORT` decides where the plugin looks for the web view (and, until Phase 4, where it starts one).

Exit: the commands work on the terminal and desktop surfaces (plugin tests), validate passes.

### Phase 2: the web app as a CLI ✔ done

1. `bin/skillverse.mjs` dispatches: no subcommand opens the terminal app (unchanged); `run [web]` starts the server in the background; `open`; `stop`; `status`; `--port`; `--help`; `--version`.
2. `run` records the pid and port in `~/.cache/skillverse/server.json`, logs to `server.log` there, and reports a server already running instead of starting a second.
3. `files` in `package.json` gains `server/`, `web/`, `bin/`.
4. `pnpm run dev` in a clone: the server in the foreground, restarting on changes to `server/`, `cli/` and `hooks/`, open pages reloading on changes to `web/`. The plugin's dev session moves to `pnpm run dev:plugin`.

Exit: `npm i -g` of the packed tarball, `skillverse run`, `/health` answers, `skillverse stop` ends it (CI).

### Phase 3: multi-agent scan ✔ done (the data; drawing moved to Phase 5)

1. One scanner per agent, all reading `SKILL.md` folders; the result says which agent each skill came from.
2. The server builds `data.js` from the scan when it starts, and on `POST /refresh`.
3. The plugin's **Open web view** sends the session's exact list (`POST /skills`, Claude only), which replaces the scanned Claude list.
4. The data marks each skill and region with its agent and links copies of a skill across agents (`twins`); `combineAgents` in `hooks/web.ts` puts the 2D graphs side by side. Drawing one globe per agent is page work and moves to Phase 5.

Exit: unit tests per scanner (fixture folders under a temporary `HOME`); the web view shows four agents on this machine.

### Phase 4: the plugin hands the web view over ✔ done

1. Remove `startServer`/`keepRunning` from the plugin.
2. **Open web view**: web app running: send the list, show the link and Open in browser. Installed but stopped: say so, with a **Start web view** button (`skillverse run`). Not installed: say so, with the install command.
3. `SKILLVERSE_WEB` is gone; `pnpm run dev` runs the web app and `pnpm run dev:plugin` the plugin.
4. As a session starts, and when a web app appears later, the plugin sends it the session's exact list (`POST /skills`).

Exit: plugin tests for the three states; the README's install section shows both parts.

### Phase 5: web view redesign and one globe per agent ✔ done

1. Refactor `web/index.html` into modules: data loading, views (globe, 3D, 2D), detail panel, live feed, controls.
2. One globe per agent side by side (a switcher on small screens), one cluster per agent in 3D, twins drawn as links across agents.
3. Design pass with the design skills (`design-brief`, `information-architecture`, `design-review`): placement of the view switcher, simulator, live follow and entries.
4. Small screens: no permanent side or bottom navigation; one sheet that opens on demand, the canvas full screen otherwise.

Exit: design review findings above "minor" fixed; checked at 375 px, 768 px and desktop widths in both themes.

### Phase 6: docs and release 0.2.0 (docs ✔ done; release pending)

1. README (two parts, install, `run`/`stop`, port), AGENTS.md, CONTEXT.md, `.jon-skills/config.yaml`. ✔
2. CHANGELOG under Unreleased. ✔
3. `pnpm version minor`, then `git push --follow-tags`.

## Risks

| Risk | Mitigation |
|---|---|
| `$.prompt.submit` spends a model turn and depends on the desktop Terminal tool | Only on the desktop surface; the prompt says to print the command when the tool is missing |
| Marketplace users without the npm package lose the web view | Open web view explains the one-line install; the pane and terminal app still work |
| Agents change their folders | One small scanner each, with fixture tests; unknown agents are simply absent |

## Design pass (Phase 5)

Read: a live developer-tool visualization for people running AI agents, glanced at beside the editor and explored when curious; dark and spatial, at low variance, purposeful motion, medium density (domains: developer-tools, ai-ml).

References (working set for this task): excalidraw, rerun, linear (read), diagrams-net (frontmatter). Taken: canvas-first chrome and canvas actions beside the canvas (excalidraw); say what a part covers and what it does not (rerun: Live names where its events come from); few type sizes, colour for status and selection only, a 4/8 rhythm, small corners, a skip link, one primary action (linear).

Review (design-review), fixed: a reload from the server dropped the selection, view and agent (scored 2); region names on small globes were unreadable (3). Left at 3: skills on the canvas are not reachable by keyboard (search and Groups are the keyboard paths).

## Orbit view (after Phase 5)

Asked for after the redesign: all agents in one view instead of split globes. Built as a fourth view and the default (`web/js/views/orbit.js`); Globes stays. One three.js scene with one three-globe per agent around a Skillverse star; planets sized by skill count, the biggest on the inner orbit, outer orbits slower; twins are bridges; click flies to a planet and the camera follows it (orbits pause while a skill is open); live activity glows, names skills (screen labels) and draws raised comet paths on the planet. The split Globes view also got a framing fix (cells sized after the first frame left globes zoomed in).

## After the Orbit view

- Globes view removed (Orbit follows planets, so a split view adds nothing).
- Memory: views are destroyed when left (WebGL context, geometry, loops), nothing draws while the tab is hidden, live arc objects are reused, the orbit view renders at up to 1.5x pixel ratio with coarser region caps. Measured JS heap: Orbit alone 103 MB to 82 MB; after visiting every view 185 MB to 99 MB; live WebGL canvases 7 to 1.
- Follow activity switch beside Fit.
- Costs (information-architecture pass): the Agents card is the one place an agent is picked (it replaced Groups and the header agent menu, two competing navigations); it carries the per-agent costs, and the reader carries the per-skill ones. Measured figures come from the plugin (`stats` in `POST /skills`); others are estimates marked ≈.
